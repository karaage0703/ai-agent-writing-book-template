# 執筆用スキルの育て方

このディレクトリのスキルは、完成した制作システムではありません。特定の著者、サービス、保存場所に依存しない共通部分だけを残した出発点です。

## 二種類のスキルがある

スキルには、コマンドを実行するものと、AIエージェントの対話や編集の順序を決めるものがあります。

- `book-setup`、`book-build`、`book-transcribe`は機械処理です。実行コマンド、出力先、成功条件まで書いてあります
- `book-ideas`、`book-interview`、`book-draft`、`book-review`などは対話・編集手順です。質問順、入力、保存形式、判断を人間へ戻す地点まで書いてあります

対話型スキルにシェルコマンドがないこと自体は問題ではありません。ただし、「適切に考える」だけで終わり、質問、出力形式、保存先、完了条件が分からないものは使えるスキルとはみなしません。

最初は、名前を指定してAIエージェントへ頼みます。

```text
book-interviewスキルを使って、第3章のために私へ一問ずつ質問してください。
```

## 実運用から残したもの

- `book-ideas`: 過去資料を検索し、資産・変換方法・読者への出口を組み合わせる実際のアイデア出し
- `book-materials`: 検索結果の抜粋で止めず、元ファイルを読み、0件時は検索語を変える探索手順
- `book-transcribe`: `transcriber_tool`の実コマンドと完了判定
- `book-draft`: 元材料、前処理、編集稿を分け、差分と組版結果を確認する書籍化手順
- `book-review`: 原稿の指摘だけでなく、リンク、画像、見出し、PDF、EPUBまで確認する実工程
- `book-visualize`: JSONからPNGを生成する実スクリプト
- `book-build`: PandocとTypstを使うテンプレート本体の生成・検査コマンド
- `book-cover`: 文字なし背景へ書名を合成する実スクリプト
- `book-publish`: 販売ファイル、紹介文、サンプル、更新履歴、公開前チェックをまとめる出版準備
- `book-feedback`: 感想、告知、販売記録、改訂候補を同じ時系列へ残す運用
- `book-revise`: 改訂候補の採否、影響調査、原稿修正、再組版、更新履歴をつなぐ改訂手順

固有の保存場所やチャット通知だけを外し、入力、処理、成果物、成功判定は削らない方針です。

## 人によって必要なスキルは違う

- アイデアを別の方法で決めるなら`book-ideas`は使わなくても構いません
- 音声を使わないなら`book-transcribe`は削除できます
- 図を手描きするなら`book-visualize`の手順を自分の道具へ合わせます
- EPUBを作らないなら`book-build`の出力と検査をPDFだけにできます
- 販売しないなら`book-publish`と`book-feedback`を削除し、`book-revise`を社内レビューや改訂記録へ合わせられます
- 材料がブログ、Notion、ローカルファイルのどこにあるかで`book-materials`の探索方法は変わります

テンプレート作者が実際に使うスキルも、ここにあるひな型とは異なります。個人の資料置き場、利用サービス、自動化スクリプト、公開手順に合わせて長く育てたものだからです。それをそのまま配るのではなく、初めて使う人が自分の環境へ合わせられる最小形に戻したものが、このテンプレートです。

## 一度使ってから直す

1. まず変更せず、一つの作業で使ってみる
2. 毎回渡した情報を`入力`へ追加する
3. 迷った判断や失敗を、短い具体例として`手順`へ戻す
4. 同じ機械操作を繰り返すなら`scripts/`を追加する
5. 長くなった参考情報は`references/`へ分ける
6. 入出力が異なる作業が混ざったら、別のスキルへ分ける
7. 使わないスキルや手順は削除する

たとえば表紙制作で、書名が背景へ埋もれたなら「文字を後から合成する」だけで終わらせず、実際に読みやすかった文字サイズ、余白、縮小確認の方法を`book-cover`へ戻します。次の表紙では、その経験から始められます。

## スキルへ追加できるもの

```text
skills/my-skill/
├── SKILL.md
├── scripts/       # 繰り返し実行する処理
├── references/    # 詳しい手順、用語集、品質基準
└── assets/        # テンプレートやサンプル
```

スキルの価値は、最初の文章量ではなく、実際の制作で得た知識を次の作業へ持ち越せることにあります。
