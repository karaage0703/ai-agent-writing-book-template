# 本のアイデア出し

## 入力

- 著者が経験したこと、得意なこと、失敗したこと
- 手元にあるブログ、メモ、コード、音声などの材料
- 想定読者、または一年前の著者が困っていたこと
- 本の形式、締切、分量などの制約

## 手順

1. 著者の経験、手元の材料、想定読者、読後の変化が不足していれば、一度に一問ずつ確認する
2. `rg --files`と`rg -n -i '<関心語>' <検索対象>`で、過去記事、メモ、コード、音声などの実在する材料を探す
3. 見つけた材料を、著者の資産、文章や音声などの変換方法、読者へ届ける出口に分ける
4. 著者の経験、少し離れた二つの資産、読者の悩み、読後の変化を組み合わせて候補を作る
5. 候補ごとに、次の項目を整理する
   - 仮の書名
   - 一文で表した内容
   - 読者のスタートとゴール
   - 著者だから書ける経験
   - 使えそうな材料
   - 不足している情報や懸念
6. 候補を比較するが、著者がテーマを選ぶまで本文を書き始めない
7. 最有力案には、半日で試せる最小版と、最初に読む元ファイルを付ける

## 判断基準

- 著者が実際に経験したことを中心にする
- 読者を広く設定しすぎない
- 材料が多いだけで候補を選ばない
- 著者が書き続けたいか、公開に責任を持てるかは本人へ確認する
- 入力にない実績、出来事、反応を作らない

## 出力

- 比較できる本のテーマ候補を五つ
- 各候補のスタート、ゴール、固有の経験、利用可能な材料
- 不足情報と、著者へ確認したい質問
- 次に人間が決めること

## 使用例

```text
book-ideasスキルを使って、私の本のテーマを一緒に考えてください。
```
